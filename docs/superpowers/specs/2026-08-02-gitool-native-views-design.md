# Gitool 原生当前变更视图设计

## 背景与目标

当前 Gitool 把提交信息、当前变更和提交历史绘制在同一个 Webview 中。当前变更列表因此只能使用扩展自己维护的 Codicon 映射，不能像 VS Code 文件树一样根据用户正在使用的文件图标主题显示 Python、Jupyter 等图标。Webview 内部模拟的分区折叠和高度计算也需要自行处理底部停靠、恢复高度和拖动边界。

VS Code 官方工作台通过内部资源标签服务解析文件图标；扩展公开 API 只在原生 `TreeItem` 上提供等价能力：文件节点设置真实 `resourceUri` 和 `ThemeIcon.File` 后，由当前文件图标主题生成图标。Webview 没有公开接口取得相同的解析结果。

本次改造把 Gitool 容器拆成三个独立 View，但只迁移“当前变更”的列表实现：

1. 提交信息：保留 Webview 和现有展示样式。
2. 当前变更：改为 VS Code 原生 TreeView，采用原生文件树样式。
3. 提交历史：保留 Webview、提交拓扑和现有展示样式。

三个 View 的折叠、展开、分隔线拖动和高度恢复交给 VS Code 工作台管理。业务服务、文件选择合同、提交历史数据和远程操作语义不变。

## 信息架构

Gitool 活动栏容器按以下顺序贡献三个 View：

```text
提交信息（Webview View）
  提交信息输入框
  AI 生成与密度选择
  仅提交 / 提交并推送

当前变更（Tree View）
  已跟踪变更（有文件时）
    目录
      文件
  未跟踪文件（有文件时）
    目录
      文件
  冲突文件（有文件时）

提交历史（Webview View）
  现有提交拓扑列表
  现有提交展开文件列表
```

三个 View 使用 VS Code 原生标题栏。用户可以分别折叠，也可以拖动 View 之间的原生分隔线。提交历史折叠后只保留位于容器底部的标题栏；再次展开时由 VS Code 恢复折叠前高度。

## 提交信息 View

提交信息继续使用 Webview，因为原生 TreeView 不适合多行输入框、AI 密度菜单和组合提交按钮。

- 保留现有输入框、AI 生成、密度选择、仅提交和提交并推送的展示样式。
- 删除 Webview 内部重复的提交信息分区标题栏，由外层 View 标题承担标题语义。
- 低频远程设置放在提交信息 View 的原生标题栏。
- 操作状态和错误继续在提交内容区域内展示。
- 多仓库选择逻辑保持不变。

## 当前变更 TreeView

### 节点与空分组

- 分组节点包括已跟踪变更、未跟踪文件和冲突文件。
- 任一分组没有文件时不返回该分组节点，不显示空标题、数量或“没有文件”。
- 目录节点只在需要表达路径层级时出现。
- 文件节点携带稳定文件 ID、仓库 ID、路径、选择状态和变更状态。
- TreeView 使用 VS Code 原生字号、行高、缩进、展开箭头、hover 和选中背景，不再由 Webview CSS模拟。

### 文件选择

- 文件节点使用 `TreeItem.checkboxState`。
- TreeView 开启手动复选框管理，继续由现有 `SelectionStore` 保存选择状态。
- 分组节点提供复选框，支持整组选择和取消。
- 未跟踪文件默认不选择。
- 未选文件及其既有暂存状态保持不变。
- 冲突文件不可选择提交，并在 tooltip 中说明原因。

### 文件图标与单行信息

- 文件节点设置仓库内真实 `resourceUri`，同时使用 `ThemeIcon.File`。
- Python、Jupyter、TypeScript 等图标由用户当前启用的 VS Code 文件图标主题解析，不维护扩展名硬编码映射。
- 文件名作为主标签，父目录作为弱化 description。
- Git 状态以简短 description、颜色和 tooltip 表达，不额外绘制大号字母列。
- 点击文件继续打开现有工作区差异。

### 标题栏与节点操作

- 刷新按钮使用 `refresh` Codicon，放在当前变更 View 标题栏。
- 舍弃使用 `trash` Codicon，只在未跟踪文件节点或未跟踪分组的菜单中出现。
- 舍弃语义保持不变：只处理已选择的具体未跟踪文件，必须二次确认并移入系统废纸篓，不永久删除。
- 当前变更标题栏继续显示已选择数量和总文件数；具体实现使用 View description 或标题更新，不在树中插入伪节点。

## 提交历史 View

提交历史继续使用 Webview，不迁移为原生 TreeView。

- 保留现有提交拓扑线、分支颜色、提交信息、作者、时间、短哈希和引用标签样式。
- 保留现有提交展开文件布局以及历史 Diff 打开行为。
- 删除 Webview 内部重复的提交历史标题栏，由外层 View 标题承担标题语义。
- 拉取、推送全部和刷新历史放在提交历史 View 的原生标题栏，分别使用官方产品图标。
- View description 显示上游名称和领先/落后数量；没有上游时显示“未设置上游”。
- 历史内容区填满 View 提供的高度，不再参与三分区高度计算。

## 分区布局状态

- 删除现有 Webview 内部 `layout-state` 三分区高度、折叠和分隔线逻辑。
- 不再渲染 Webview 内部的三个折叠按钮和两条拖动分隔线。
- 由 VS Code 工作台负责三个独立 View 的折叠、展开、拖动、最小标题高度和高度持久化。
- 提交历史折叠时停靠在 Gitool 容器最下方，只占一行标题栏；展开后恢复折叠前高度。
- 当前变更由原生 TreeView 自己滚动，提交信息和历史 Webview 仅在各自内容区滚动。

## 状态同步与架构边界

现有仓库服务和写入协调器继续作为唯一业务状态来源，不把 Git 操作复制到 View Provider 中。

- `RepositoryService` 继续生成统一仓库快照。
- 提交 Webview、变更 TreeDataProvider 和历史 Webview 订阅同一份当前仓库状态。
- 文件复选框变化写回现有选择存储，并同步刷新提交 View 的已选择数量和按钮可用状态。
- 提交、舍弃、拉取、推送、远程设置成功后通过统一刷新入口更新三个 View。
- 过期快照、冲突、未信任工作区、仓库锁和多仓库隔离保持不变。
- 只有当前仓库被操作；仓库选择入口仍位于提交信息 View。

## 命令与菜单

新增或调整的命令均在 `package.json` 声明中文标题和官方 Codicon：

- 修改远程设置；
- 刷新当前变更；
- 舍弃未跟踪文件；
- 打开当前文件变更；
- 拉取当前分支；
- 推送全部本地提交；
- 刷新提交历史。

标题栏只放高频操作。低频远程设置位于提交信息标题栏；舍弃只在目标节点满足条件时出现，避免永久显示无效按钮。

## 可访问性与错误处理

- 所有图标命令提供明确的中文标题和 tooltip。
- 不用颜色作为唯一状态表达，文件状态同时进入 description 或 tooltip。
- TreeView 复选框使用 VS Code 原生键盘和屏幕阅读器行为。
- 加载状态使用 TreeView message 或 VS Code 进度提示，不插入伪文件节点。
- 错误继续显示明确原因和下一步，不静默失败。

## 迁移步骤

1. 声明提交信息、当前变更和提交历史三个独立 View，以及对应标题栏命令。
2. 实现当前变更 TreeDataProvider，接回选择、分组、Diff 和废纸篓操作。
3. 把现有 Webview 拆成提交信息与提交历史两个受限页面，共享同一仓库状态。
4. 删除 Webview 内部已迁移的变更列表、文件图标映射和三分区布局逻辑。
5. 验证三个 View 的状态同步、原生折叠拖动与现有提交历史展示。

迁移期间不改变提交、推送、拉取、远程设置和废纸篓服务的业务合同。

## 测试与验收

### 单元测试

- 数量为零的已跟踪、未跟踪和冲突分组不会生成 TreeItem。
- 文件节点使用真实 `resourceUri`、`ThemeIcon.File`、正确 description 和 checkboxState。
- 未跟踪文件默认未选，分组选择正确同步到 `SelectionStore`。
- 舍弃命令只接受当前仓库内已选择的具体未跟踪文件。
- 提交 Webview 只包含现有提交输入内容，不包含当前变更或内部布局控制。
- 历史 Webview 保留现有拓扑和展开标记，不包含内部布局控制。
- 标题栏命令的 `when` 条件和菜单位置正确。

### Extension Host 验收

- 三个 View 可独立折叠，原生分隔线可拖动。
- 提交历史折叠后位于底部且只占标题栏，展开后恢复之前高度。
- 当前变更的空分组不显示。
- Python、Jupyter 等文件跟随当前 VS Code 文件图标主题。
- 文件选择后，提交信息 View 的选择数量和按钮状态同步更新。
- 点击当前文件打开正确 Diff，垃圾桶操作保留二次确认并移入系统废纸篓。
- 拉取、推送、刷新和远程设置从对应原生标题栏正常触发。
- 提交历史的拓扑、分支颜色、引用标签和展开样式与改造前一致。

### 完整回归

- `npm run check`
- `env -u ELECTRON_RUN_AS_NODE npm run test:vscode`
- `npx vsce ls --no-dependencies`
- `npm run package`

## 非目标

- 不把提交历史迁移为原生 TreeView。
- 不改变现有提交历史的视觉样式。
- 不实现文件内代码块选择提交。
- 不重写现有 Git 服务、写入锁或历史服务。
- 不读取或解析用户文件图标主题的私有文件。
- 不引入第三方图标包。
