# Gitool 原生三分区视图设计

## 背景与目标

当前 Gitool 把提交信息、当前变更和提交历史全部绘制在同一个 Webview 中。文件图标、按钮图标、树形展开、提交图线、字号、行高以及分隔线均由扩展自行模拟。这导致界面与 VS Code 原生交互存在明显差异：列表字号和行高偏大，历史提交展开后层级割裂，手绘图线不连续，文字操作占用横向空间，文件图标无法跟随用户当前的文件图标主题。

本次改造把侧边栏拆成三个真正独立的 VS Code View：

1. 提交信息：保留精简 Webview，承载文本输入、AI 生成和提交操作。
2. 当前变更：改为原生 TreeView，承载文件选择、分组和变更查看。
3. 提交历史：改为原生 TreeView，承载提交记录、引用位置和历史文件展开。

目标是使用 VS Code 自己的列表密度、字号、展开层级、文件图标主题、标题栏操作和可拖动视图区间，不再用 CSS 模拟原生工作台。

## 信息架构

Gitool 活动栏容器内按顺序贡献三个 View：

```text
提交信息（Webview View）
  提交信息输入框
  AI 生成与密度选择
  仅提交 / 提交并推送
  操作状态与错误

当前变更（Tree View）
  已跟踪变更
    文件
  未跟踪文件
    目录
      文件
  冲突文件（存在时）

提交历史（Tree View）
  提交
    本次提交涉及的文件
  提交
  提交
```

三个 View 使用 VS Code 原生标题栏。用户可分别折叠，也可直接拖动 View 之间的分隔线调整高度。扩展删除现有 Webview 内部的折叠状态、拖动状态和最小高度计算。

## 提交信息 View

提交信息继续使用 Webview，因为原生 TreeView 不适合多行输入框、AI 密度菜单和组合提交按钮。

- 删除 Webview 内部重复的“提交信息”标题栏，只保留内容区。
- 输入框采用 VS Code 表单变量，正文使用编辑器默认字号，不额外放大。
- “远程设置”从三点字符改为原生 View 标题栏命令，使用 `remote` 产品图标。
- AI 生成仍保留文字标签和密度名称，因为它们表达当前模式，不能仅靠图标传达。
- “仅提交”和“提交并推送”保留文字，避免两个高风险动作只靠相似图标区分。
- 错误信息继续内联展示；无远程时明确提示如何添加远程。

## 当前变更 TreeView

### 节点模型

- 分组节点：已跟踪变更、未跟踪文件、冲突文件。
- 目录节点：仅在需要表达真实路径层级时出现。
- 文件节点：携带稳定文件 ID、仓库 ID、路径、选择状态和变更状态。

### 文件选择

- 文件节点使用 `TreeItem.checkboxState`。
- TreeView 开启手动复选框管理，继续由现有 `SelectionStore` 保存选择状态。
- 分组节点可提供复选框，实现整组选择与取消；部分选择状态不伪造成全选。
- 未跟踪文件仍默认不选择。
- 未选文件及其既有暂存状态保持不变。
- 冲突文件不可选择提交，并在 tooltip 中说明原因。

### 文件图标与状态

- 文件节点设置真实 `resourceUri`，并使用 `ThemeIcon.File`，由 VS Code 根据用户当前文件图标主题解析图标。
- 不再维护扩展名到字符图标的硬编码映射。
- 文件名作为主标签；父目录作为弱化 description，保持单行。
- Git 状态使用 `ThemeColor` 和简短 description/装饰表达，不额外占一列绘制大号字符。
- 点击文件执行现有变更对比命令。

### 操作

- 刷新使用 `refresh` Codicon，放在 View 标题栏。
- 当前变更的 `refresh` 命令刷新工作区和本地历史状态；不保留单独的“获取远程状态”按钮，真正联网只由拉取或推送命令触发。
- 舍弃未跟踪文件使用 `trash` Codicon，作为未跟踪文件节点或分组的行内/上下文操作。
- 舍弃语义不变：只允许已选择的具体未跟踪文件，必须二次确认，并移入系统废纸篓，不永久删除。

## 提交历史 TreeView

### 提交节点

- 每条提交是可折叠节点，使用 `git-commit` Codicon。
- 主标签显示提交信息，保持单行并交给 VS Code 原生截断。
- description 在同一行显示“作者 · 相对时间 · 短哈希”。
- HEAD、本地分支和远程分支位置通过原生产品图标、简短标签或 tooltip 表达；不再绘制大号胶囊。
- 当前 HEAD 可使用 `target`/`circle-filled` 图标或强调色区分，但不改变整行字号和高度。

### 展开文件

- 展开提交后，子节点直接由 TreeView 原生缩进和折叠机制呈现。
- 子文件设置对应仓库路径的 `resourceUri` 和 `ThemeIcon.File`，使用当前文件图标主题。
- 文件名为主标签，目录为 description，状态作为短 description 或 tooltip 补充。
- 点击历史文件继续打开该提交与父提交之间的 diff。
- 删除现有手绘提交轨道和分段竖线。原生树层级本身表达父子关系，不叠加一套容易断裂的图形语言。

### 同步操作

- 拉取、推送全部、刷新历史放在“提交历史”View 标题栏。
- 分别使用 `cloud-download`、`cloud-upload`、`refresh` Codicon。
- 推送全部仍遵循仓库配置，把当前分支所有未推送提交推送到既有上游。
- View 的 description 显示上游名称以及领先/落后数量；没有上游时显示“未设置上游”。

## 状态同步与架构边界

现有仓库服务和写入协调器继续作为唯一业务状态来源，不把 Git 操作复制到各 View Provider 中。

- `RepositoryService` 继续生成统一仓库快照。
- 提交 Webview、变更 TreeDataProvider、历史 TreeDataProvider 订阅同一份选中仓库状态。
- 文件复选框变化写回现有选择存储，并触发提交 View 的“已选择数量”和按钮可用状态刷新。
- 提交、舍弃、拉取、推送、远程设置成功后，通过统一刷新入口更新三个 View。
- 过期仓库快照、冲突、未信任工作区等现有写入保护保持不变。
- 多仓库仍每次只操作一个仓库；仓库选择入口保留在提交信息 View 内，只有多个仓库时显示。

## 命令与菜单

新增或调整的命令均在 `package.json` 声明中文标题和 Codicon：

- 修改远程设置
- 刷新当前变更
- 舍弃未跟踪文件
- 拉取当前分支
- 推送全部本地提交
- 刷新提交历史
- 打开当前文件变更
- 打开历史文件变更

标题栏最多显示三个高频操作；低频远程设置放到提交信息 View 的标题栏或更多菜单。舍弃只在目标节点满足条件时出现，避免永久显示无效操作。

## 可访问性与错误处理

- 所有图标命令提供明确的中文标题、tooltip 和 `aria-label` 对应语义。
- 不用颜色作为唯一状态表达；文件状态同时提供文本或 tooltip。
- TreeView 复选框使用 VS Code 原生键盘和屏幕阅读器行为。
- 加载状态使用 TreeView message 或 VS Code 进度提示，不在列表中插入伪节点。
- 错误继续通过明确的中文消息说明原因和下一步，不静默失败。

## 迁移策略

采用分阶段替换，避免一次迁移破坏现有 Git 写入链路：

1. 建立共享 View 状态适配层和原生命令。
2. 迁移当前变更到 TreeView，并接回选择、diff 和舍弃操作。
3. 迁移提交历史到 TreeView，并接回展开加载和历史 diff。
4. 精简提交信息 Webview，删除内部标题栏和已迁移区域。
5. 删除不再使用的历史渲染器、文件字符图标映射、布局拖动状态和对应 CSS。

迁移期间不改变提交、推送、拉取、远程设置和废纸篓服务的业务合同。

## 测试与验收

### 单元测试

- TreeItem 文件节点使用真实 `resourceUri`、`ThemeIcon.File`、正确 description 和 checkboxState。
- 未跟踪文件默认未选，分组选择正确同步到 `SelectionStore`。
- 舍弃命令只接受当前仓库内已选择的具体未跟踪文件。
- 历史提交节点和子文件节点的标签、description、图标、展开与 diff 参数正确。
- 标题栏命令的 `when` 条件和菜单位置正确。
- 提交 Webview 不再包含内部三个分区、手绘历史图线或字符文件图标。

### Extension Host 验收

- 三个 View 可独立折叠，分隔线可拖动。
- 当前变更与历史文件均跟随当前 VS Code 文件图标主题。
- 文件选择后，提交信息 View 的选择数量和按钮状态同步更新。
- 点击当前文件和历史文件分别打开正确 diff。
- 垃圾桶操作保留二次确认并移入系统废纸篓。
- 拉取、推送、刷新和远程设置从原生标题栏正常触发。
- 提交历史展开使用原生连续树层级，不再出现手绘断线。

### 完整回归

- `npm run check`
- `env -u ELECTRON_RUN_AS_NODE npm run test:vscode`
- `npx vsce ls --no-dependencies`
- `npm run package`

## 非目标

- 不实现文件内代码块选择提交。
- 不重写现有 Git 服务和写入锁。
- 不读取或解析用户已安装文件图标主题的私有文件。
- 不引入第三方图标包。
- 不增加 Git 图谱的分叉线路绘制；历史层级优先采用 VS Code 原生树交互。
