# Gitool 提交历史紧凑展开设计

## 背景

当前提交历史展开后，文件列表使用独立的整块选中背景，并从提交轨道右侧重新绘制一条边线。提交行与文件区因此像两个拼接模块；文件行只显示完整路径，横向信息利用率也低于 VS Code 自带图表。

## 方案比较

### 方案 A：跟随 VS Code 图表结构（采用）

提交轨道连续贯穿展开文件区，只高亮当前提交行。文件行显示文件名、灰色目录和最右侧状态，使用紧凑行高。

优点是视觉连续、信息密度高，并与用户熟悉的 VS Code 交互一致；代价是需要调整文件展示模型和对应测试。

### 方案 B：保留现有结构，仅缩小行高

改动最少，但整块背景和错位轨道仍会造成割裂，不能解决主要问题。

### 方案 C：展开后显示表格列

文件名、目录和状态对齐最稳定，但在窄侧栏中容易横向拥挤，也偏离 VS Code 图表体验。

## 视觉与交互

- 提交行最小高度从 36px 收紧到 32px。
- 展开文件行最小高度为 28px。
- 提交行左侧图表轨道保持原位置，并由同一个 `graph-cell` 视觉列连续延伸到所有展开文件行。
- 展开时只使用提交行选中背景，文件列表使用普通侧栏背景。
- 文件行不增加外围边框、卡片背景或额外左侧嵌套边线。
- 文件行从轨道之后开始排列：文件类型图标、文件名、灰色目录、Git 状态。
- 文件名为主要信息，单行省略；目录为次要信息，单行省略；Git 状态固定在最右侧。
- 点击提交行继续展开或收起，点击文件行继续打开对应历史 Diff；键盘与 ARIA 语义保持不变。

## 渲染结构

`history-renderer.ts` 将历史文件路径拆分为两段：

- `basename`：最后一个路径段，例如 `render.ts`。
- `directory`：其余目录，例如 `src/webview`；根目录文件的目录为空且不渲染占位文本。

每个文件按钮内部使用以下稳定结构：

```html
<span class="commit-file-graph" aria-hidden="true"></span>
<span class="commit-file-icon">TS</span>
<span class="commit-file-name">render.ts</span>
<span class="commit-file-directory">src/webview</span>
<span class="commit-file-status">M</span>
```

文件图标复用现有 `resolveFileIcon` 规则，保证历史文件与当前变更使用一致的类型图标和颜色；未知类型继续使用通用图标。

## 样式边界

- `.commit-files` 不再设置左外边距、独立左边框或选中背景。
- `.commit-file` 使用与提交行相同的图表列宽，使轨道水平位置一致。
- `.commit-file-graph::before` 绘制贯穿整行的 2px 蓝色轨道，不绘制额外节点。
- 展开提交的圆点保持实心，用于表达当前展开位置。
- hover 仅作用于当前文件行，不改变整块文件区。
- 窄宽度下优先保留文件名和状态；目录先被压缩并省略。

## 非目标

- 不在本次增加多分支、多泳道图算法。
- 不改变提交排序、引用标签、作者时间和哈希数据。
- 不改变历史详情加载、缓存或 Diff 打开协议。
- 不增加新的用户配置项；紧凑布局作为统一默认样式。

## 测试与验收

- 单元测试验证文件路径正确拆分为文件名和目录，根目录文件不产生虚假目录。
- 单元测试验证历史文件复用文件类型图标，并保留 Git 状态和原始 `data-path`。
- 样式回归测试验证文件区不再使用独立卡片背景或错位边线，并使用连续轨道列。
- 现有展开、收起和打开历史 Diff 测试继续通过。
- 运行类型检查、lint、全量 Vitest、Extension Host 测试、构建与 VSIX 打包。
