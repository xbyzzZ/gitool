# Gitool 原生提交历史设计

## 变更范围

本设计把 Gitool 的“提交历史”从 Webview 迁移为 VS Code 原生 TreeView。它只修订《Gitool 原生当前变更视图设计》中“提交历史继续使用 Webview”的部分；提交信息 Webview、当前变更 TreeView、Git 写入服务和远程同步合同保持不变。

迁移目标是获得与 VS Code 原生列表一致的字号、行高、选中状态、键盘操作、折叠行为和文件主题图标。原生 TreeView 不支持自定义多分支拓扑线，因此不再绘制现有彩色提交线路。

## 信息结构

提交历史使用按时间排序的平铺根节点，不按父子提交关系嵌套：

```text
提交历史（TreeView）
  提交 A：提交信息 · 作者 · 时间 · 短哈希 · 分支引用
    改动文件 1
    改动文件 2
  提交 B：提交信息 · 作者 · 时间 · 短哈希 · 分支引用
  提交 C：提交信息 · 作者 · 时间 · 短哈希 · 分支引用
```

根节点顺序完全沿用 `HistoryService` 返回的提交顺序。合并提交仍只出现一次，不因多个父提交而复制节点。

## 提交节点

- 主标签使用完整提交信息，空间不足时由 VS Code 原生省略号截断，完整内容进入 tooltip。
- description 按固定顺序显示作者、相对时间、短哈希和引用名称，保持单行展示。
- 引用名称中，当前分支显示为 `HEAD main`，本地分支和远程分支保留 Git 返回的原名。
- 提交图标按 `HEAD > 本地分支 > 远程分支 > 普通提交` 的优先级选择官方 ThemeIcon，并使用不同 ThemeColor；tooltip 同时写明引用类型，因此颜色不是唯一表达方式。
- 有提交详情能力的节点默认可折叠。首次展开时按仓库 ID、仓库版本和提交哈希读取详情；同一快照内重复展开复用缓存。
- 仓库切换、仓库版本变化或历史刷新后清空不再适用的详情缓存，禁止把旧仓库文件挂到新历史节点下。

## 文件节点

- 提交详情中的文件按 Git 返回顺序展示为提交节点的直接子节点，不再增加中间分组。
- 文件名作为主标签，父目录和 Git 状态作为 description。
- 文件节点设置仓库内真实 `resourceUri` 和 `ThemeIcon.File`，由用户当前启用的 VS Code 文件图标主题解析 Python、Jupyter、TypeScript 等文件图标。
- 重命名文件的 tooltip 同时展示原路径和新路径。
- 点击文件调用现有历史 Diff 逻辑：新增文件使用空文档与提交版本比较，删除文件使用提交版本与空文档比较，其他文件比较父提交与当前提交。
- 文件节点不提供复选框，不参与当前变更的提交选择状态。

## 标题栏与同步状态

- `gitool.historyView` 从 Webview View 改为普通 Tree View，位置仍在 Gitool 容器最下方。
- 拉取、推送全部和刷新历史继续位于提交历史原生标题栏，命令 ID 和业务语义不变。
- TreeView description 继续显示上游名称以及 `↑领先 ↓落后`；无上游显示“未设置上游”，游离 HEAD 显示“游离 HEAD”。
- 折叠、展开、区域高度恢复和与上方 View 的分隔线拖动完全由 VS Code 工作台负责。

## 状态与错误处理

- `RepositoryService` 仍是历史与同步状态的唯一来源，TreeDataProvider 只读取快照和请求提交详情。
- 历史加载中，TreeView message 显示“正在读取提交历史…”，已有提交节点保持可见。
- 空历史显示“暂无提交记录”。
- 历史刷新失败时保留上一批提交节点，TreeView message 显示服务返回的明确错误。
- 提交详情加载失败时不写入空缓存；错误通过统一 `reportFailure` 状态上报，下一次展开允许重试。
- 过期仓库版本、仓库切换和已关闭仓库继续被现有版本校验拒绝。

## 代码边界

- 新增 `HistoryTreeProvider`，负责提交节点、文件节点、原生图标、description、tooltip、缓存和 View 元数据。
- 原生命令控制器新增历史文件 Diff 命令，只做节点范围校验和 URI 组织，继续复用 `BuiltinGitApi.toGitUri`。
- `RepositoryService`、`HistoryService` 和历史数据模型不为界面迁移重写。
- 删除历史 Webview Provider、历史客户端、历史 HTML、拓扑渲染器以及仅供该 Webview 使用的文件图标映射和 CSS。
- 提交信息 Webview Provider 不再承担历史消息处理，Provider 的消息边界收紧到提交与 AI 操作。

## 测试与验收

### 单元测试

- 根节点保持服务返回的时间顺序，合并提交只出现一次。
- 提交节点单行包含提交信息、作者、相对时间、短哈希和全部引用名称。
- HEAD、本地分支、远程分支和普通提交选择正确的原生图标语义。
- 展开提交只在当前仓库快照内懒加载一次详情；刷新或切换仓库后旧缓存失效。
- 历史文件节点使用真实 `resourceUri` 和 `ThemeIcon.File`，description 包含目录与状态。
- 点击新增、删除、修改及重命名文件打开正确的历史 Diff。
- 加载、空历史和失败状态更新正确的 TreeView message，同时不丢弃可用旧节点。
- `package.json` 将提交历史声明为普通 Tree View，并保留三个标题栏命令。
- 提交信息 Webview HTML 不包含历史列表，构建产物不再包含历史 Webview 脚本。

### Extension Host 与人工验收

- 提交历史显示为原生紧凑列表，可使用键盘选择和展开。
- 提交信息、作者、时间、短哈希及引用在同一行表达。
- Python、Jupyter 等历史文件跟随当前 VS Code 文件图标主题。
- 点击历史文件打开正确 Diff。
- 拉取、推送全部和刷新历史正常工作，上游与领先/落后状态正确更新。
- 提交历史折叠后停靠在容器底部，再次展开恢复原高度。

## 非目标

- 不用 TreeView 模拟或重建彩色多分支拓扑线。
- 不按分支复制提交，不把提交历史改成分支目录树。
- 不改变 Git 历史查询范围、排序、提交数量和远程同步语义。
- 不改变提交信息和当前变更的展示与交互。
- 不读取 VS Code 文件图标主题的私有配置文件，不引入第三方图标包。
