# Gitool 提交工作台重构设计

## 1. 背景与目标

当前 Gitool Webview 已具备按文件选择、提交、推送、修改远程 URL 和将未跟踪文件移入废纸篓等能力，但页面仍是线性表单结构：仓库信息占据首屏、文件只有 Git 状态字符、功能区边界弱、底部提交框与文件列表割裂，也无法查看本地与远程提交位置。

本次重构以 VS Code 原生源代码管理交互为参照，保留其紧凑、可预期的操作语言，同时补足原生界面缺少的“按文件选择提交”能力。最终界面固定为三个功能区：

1. 提交信息；
2. 当前变更；
3. 提交历史。

三个功能区是后续实现和验收的固定骨架，不得为了局部展示或窄屏适配删除任一区域。

## 2. 设计原则

- 高频功能直接展示，低频功能收进小图标或溢出菜单。
- 文件选择是 Gitool 的核心差异，任何改版都必须保持按文件勾选、组选择和未选文件暂存状态不变的现有语义。
- 复用 VS Code 主题颜色、焦点样式、活动栏徽标和紧凑控件密度，不另造独立视觉品牌。
- 提交、拉取、推送、远程修改和废纸篓操作仍由扩展宿主执行；Webview 只负责展示、选择和发送经过版本绑定的请求。
- 不自动 stash、不静默处理冲突、不修改用户 Git 拉取策略、不在未经用户点击时调用 AI。

## 3. 页面骨架

### 3.1 提交信息区

提交信息区位于顶部，包含：

- 当前选择摘要，例如“已选择 2 / 4”；
- 提交信息输入框；
- “AI 生成”分裂按钮；
- “仅提交”按钮；
- “提交并推送”主按钮；
- 右上角远程设置小图标。

不再单独展示当前仓库与分支卡片。只有工作区同时打开多个 Git 仓库时，才在提交信息区标题栏显示紧凑仓库选择器；单仓库时完全隐藏。分支和上游信息在提交历史区通过引用标签和同步摘要表达。

远程设置属于低频操作，只保留图标按钮和悬停说明，不占用独立区域。

### 3.2 当前变更区

当前变更区位于中部，标题栏包含：

- 当前变更文件总数；
- 已选择文件数；
- 刷新按钮；
- 折叠按钮。

一级按状态分区：

- 待提交：已跟踪且无冲突的变更；
- 未跟踪：默认不选中；
- 冲突：单独展示，禁止提交写操作。

每个状态分区内按目录进行弱分组。目录只负责辅助扫描路径，不改变提交粒度；真正的选择项仍然是具体文件。目录组和状态组均可折叠。

文件行从左到右包含：

1. 复选框；
2. 文件类型图标；
3. 文件名；
4. 弱化显示的目录路径；
5. Git 状态标记。

文件类型图标与 Git 状态必须分离。首版通过本地扩展名映射提供常见类型图标，并使用通用文件图标处理未知类型；不依赖网络资源，也不读取用户文件图标主题的私有实现。

点击文件名继续打开当前变更差异。未跟踪文件打开普通文本内容。未跟踪分区保留“移入废纸篓”操作和二次确认，不使用永久删除或 `git clean`。

### 3.3 提交历史区

提交历史区位于底部，标题栏在同一行展示：

- “提交历史”；
- 上游名称，例如 `origin/main`；
- 本地领先数和落后数，例如 `↑3 ↓0`；
- 从远程拉取；
- 推送全部；
- 刷新历史；
- 折叠。

拉取、推送、刷新和折叠均使用紧凑图标按钮，悬停显示完整动作说明。不得再为同步操作增加第二行工具栏。

历史使用提交图展示最近 50 条记录，按拓扑和日期顺序排列。图中必须标明：

- 当前 `HEAD`；
- 当前本地分支，例如 `main`；
- 当前上游远程跟踪分支，例如 `origin/main`。

每条未展开的提交记录严格占一行，从左到右包含：

1. 展开箭头；
2. 提交信息；
3. 提交人；
4. 相对提交时间；
5. 7 位提交短哈希；
6. 位于该提交上的本地或远程引用标签。

提交信息占弹性空间，过长时显示省略号并通过悬停展示全文。提交人、时间、短哈希和引用标签保持单行。只有用户展开提交后，改动文件才占用后续行。

展开提交后懒加载该提交的文件列表。点击历史文件打开只读差异：该提交的父版本与该提交之间的改动；根提交以空树作为左侧版本。合并提交首版与第一父提交比较，并在界面说明比较基准。

## 4. 可调整布局

三个功能区均可折叠。提交信息区与当前变更区之间、当前变更区与提交历史区之间各放置一条纵向拖拽分隔条。

- 提交信息区最小高度为 116 像素；
- 当前变更区展开时最小高度为 96 像素；
- 提交历史区展开时最小高度为 100 像素；
- 折叠后只保留标题栏；
- 拖动时分隔条使用 VS Code 焦点色高亮；
- 双击分隔条恢复默认比例；
- 拖动结果和折叠状态按工作区及仓库记录；
- 窗口高度不足时按最小高度重新约束，不能把任一区域拖到不可操作。

Webview 使用 `acquireVsCodeApi().getState()` 和 `setState()` 保存纯界面布局状态，按仓库 ID 建立记录。仓库业务状态仍由扩展宿主管理。

## 5. 活动栏徽标

Gitool 活动栏图标使用 VS Code `WebviewView.badge` 显示当前仓库的全部变更文件数。

- 计数以合并后的唯一 `FileChange` 数量为准；
- 包含已跟踪、未跟踪和冲突文件；
- 与文件是否勾选无关；
- 当前仓库无变更或没有打开仓库时移除徽标；
- 徽标提示说明具体数量；
- 多仓库时徽标跟随当前选中的仓库。

## 6. 远程同步语义

### 6.1 同步状态

当当前分支存在上游时，通过 Git 计算：

```text
git rev-list --left-right --count HEAD...@{upstream}
```

得到当前本地分支相对上游远程跟踪分支的领先和落后提交数。“当前变更”区的刷新只更新本地状态，不隐式联网；“提交历史”区的刷新由用户明确触发，先 fetch 当前上游远程但不合并，再重新计算历史、引用位置和计数。拉取或推送完成后同样重新计算。

游离 `HEAD` 时显示 `HEAD` 位置，但禁用拉取和推送。

### 6.2 从远程拉取

“从远程拉取”调用 VS Code 内置 Git API 的拉取能力，遵循仓库已有 Git 配置，包括 `pull.rebase` 和分支级配置。

- 不自动 stash；
- 不修改 Git 配置；
- 不用强制参数覆盖用户策略；
- 无上游时禁用并说明原因；
- 冲突或本地改动阻止拉取时保留 Git 原始错误并进行敏感信息遮蔽；
- 成功后刷新当前变更、历史、引用位置和领先/落后数。

### 6.3 推送全部

“推送全部”与“提交并推送”的精确提交重试语义不同。它用于把当前本地分支相对上游尚未推送的全部可达提交一次推送到远程。

- 已有上游时执行当前分支的标准推送；
- 按钮旁显示待推送提交数；
- 领先数为零时禁用；
- 本地落后或已分叉时不执行强制推送，提示先拉取并解决分歧；
- 无上游时选择已有远程，为当前同名分支建立上游后推送；
- 不支持强制推送；
- 推送成功后刷新历史、引用位置和同步计数。

现有“提交并推送”仍保持“先创建本地提交，再推送”的流程；推送失败时保留提交哈希和精确重试能力。

## 7. VS Code 原生 AI 提交信息

### 7.1 接入边界

AI 生成只使用 VS Code Language Model API：

- 通过 `vscode.lm.selectChatModels()` 获取 VS Code 当前可用模型；
- 不在 Gitool 中增加 API Key、模型地址或供应商配置；
- 不把 GitHub Copilot 声明为扩展的强依赖；
- 只在用户点击“AI 生成”后选择模型和发送请求；
- 第一次调用由 VS Code 展示原生授权；
- 无可用模型、用户拒绝授权、额度受限或请求失败时显示明确原因；
- AI 不可用不能影响手写提交和其他 Git 功能。

模型选择不固定具体 family、version 或 id，避免模型下线导致功能失效。优先选择 VS Code 返回的可用 Copilot 文本模型；不存在时再使用其他可用文本模型。模型选择细节不暴露为 Gitool 配置。

### 7.2 上下文

AI 只分析当前勾选文件相对 `HEAD` 的差异，不能把未选文件加入上下文。生成前重新校验仓库版本和选择范围。

- 已跟踪文件使用与提交语义一致的完整文件差异；
- 未跟踪文本文件包含路径和受限长度内容；
- 二进制文件只提供路径和状态，不发送二进制内容；
- 单文件和总上下文均设置字节及模型 token 上限；
- 使用现有敏感信息遮蔽逻辑处理 URL 凭据和常见令牌参数；
- 超限或被排除文件必须在界面反馈中列明，不能静默忽略。

生成结果只填充提交信息输入框，绝不自动提交。用户可以继续编辑或重新生成。

### 7.3 信息密度

“AI 生成”采用分裂按钮。主体按上次选择的密度直接生成，箭头切换密度。密度按工作区记录：

- 精简：只生成一行中文标题；
- 标准：中文标题加 2–4 条关键变化，默认选择；
- 详细：中文标题加完整正文，描述行为变化、兼容影响和建议验证项。

所有档位都必须遵守：

- 使用简体中文；
- 不输出 Markdown 代码围栏；
- 不虚构未执行的测试、部署或验收；
- 不生成与所选差异无关的内容；
- 保持现有仓库“类型：摘要”的中文提交风格。

生成期间按钮显示进度并允许取消。新的选择、仓库切换或状态版本变化会取消过期生成结果，不能把旧结果写入新仓库输入框。

## 8. 数据和服务边界

### 8.1 ViewModel 扩展

`RepositoryViewModel` 增加：

- 当前变更总数；
- 当前仓库同步状态；
- 上游显示名；
- 领先和落后数；
- 最近提交摘要及图关系；
- 历史加载、错误和分页状态；
- AI 可用性与生成状态。

历史提交文件详情采用按需消息加载，不随每次仓库状态刷新传输全部文件。

### 8.2 新服务

- `HistoryService`：读取提交、父子关系、引用、提交文件及历史差异 URI；
- `SyncService`：计算领先/落后、拉取、标准分支推送和无上游建立；
- `CommitMessageAiService`：裁剪差异上下文、选择 VS Code 模型、构建提示、解析和校验生成结果；
- `FileIconResolver`：将路径映射为本地文件类型图标和颜色令牌。

所有写操作继续经过仓库级锁、主动 `status()` 和快照校验。历史读取和 AI 上下文读取不得绕开路径校验和敏感信息遮蔽。

## 9. 错误与空状态

- 没有仓库：三个功能区保留标题，正文提示打开 Git 仓库；活动栏无徽标。
- 没有变更：当前变更区显示“工作区没有变更”；提交和 AI 生成禁用。
- 没有提交：历史区显示“仓库还没有提交记录”。
- 没有上游：显示“未设置上游”；拉取禁用，推送进入已有远程选择流程。
- 拉取冲突：显示 Git 错误并刷新冲突分区，不自动解决。
- 推送被拒：显示非快进或权限原因，不尝试强制推送。
- AI 无模型：提示 VS Code 当前没有可用 AI 模型，不引导用户填写 Gitool API Key。
- AI 未授权：保留输入框内容，说明授权未完成。
- 历史读取失败：不影响当前变更和本地提交功能。

## 10. 测试与验收

### 10.1 单元测试

- 三功能区 HTML 结构始终存在；
- 状态分区、目录弱分组和文件图标映射；
- 活动栏徽标计数及清除；
- 折叠、拖动、最小高度、双击复位和状态持久化；
- Git 历史 NUL 分隔解析、父提交关系、引用位置和单行渲染；
- 领先/落后解析及按钮可用状态；
- 拉取和推送消息校验；
- AI 三档提示、上下文裁剪、结果校验、取消及错误映射；
- Webview 过期请求和跨仓库结果拒绝。

### 10.2 Git 集成测试

使用隔离临时仓库覆盖：

- 本地领先多个提交时“推送全部”完整同步；
- 本地落后和分叉时禁止非快进推送；
- 拉取遵循 merge 与 rebase 配置；
- 无上游选择远程并建立同名上游；
- 本地与远程引用落在不同提交时图和计数正确；
- 根提交、合并提交、重命名、删除和二进制文件的历史详情；
- 历史文件差异打开正确版本。

### 10.3 Extension Host 验收

- 活动栏徽标随真实仓库变化更新；
- 三功能区显示、折叠和拖动；
- 按文件精确提交及原有暂存状态保持；
- 历史展开和差异打开；
- 拉取、推送全部、无上游建立和推送失败反馈；
- 使用模拟服务验证 AI 按钮、密度和结果写入，真实模型调用不进入自动测试配额。

### 10.4 交付验收

每次交付必须运行：

```bash
npm run check
npm run build
npm run test:vscode
npx vsce ls --no-dependencies
```

`.vscodeignore` 必须排除 `.worktrees/**`、`.serena/**`、源码、测试和其他开发期目录，防止当前未跟踪工具目录污染 VSIX。

## 11. 明确不做

- 文件内代码块选择提交；
- 创建或删除远程；
- 强制推送；
- 自动解决拉取冲突；
- 自动 stash 或丢弃用户改动；
- AI 自动提交；
- Gitool 自建模型供应商或保存用户 API Key；
- 首版无限历史、提交搜索、标签管理和交互式 rebase。
