# Gitool AI 信息密度星级图标设计

## 目标

AI 生成按钮使用星星数量表达当前提交信息密度，同时保持按钮和图标整体尺寸稳定：

- 精简：1 颗星；
- 标准：2 颗星；
- 详细：3 颗星。

密度变化只影响图标内部构图，不改变按钮布局、宽高、相邻下拉按钮位置或提交操作按钮位置。

## 视觉规格

- AI 生成按钮继续保持 `28 × 28px`。
- 星级图标固定使用 `16 × 16px` 内部画布。
- 星形复用 VS Code Codicon `sparkle-filled.svg` 中的单颗星矢量轮廓，并以内联 SVG 渲染，不新增图片资源。
- 精简状态在画布中央显示一颗主星。
- 标准状态在同一画布内按左上主星、右下辅星构图。
- 详细状态在同一画布内按左侧主星、右上与右下辅星构成三角布局。
- 星星数量增加时缩小单颗星并重新排布，三个状态的外接边界均限制在 `16 × 16px`，不得造成按钮视觉尺寸增长。
- 星形颜色继承按钮前景色，以适配 VS Code 当前主题及按钮禁用状态。

## 状态与交互

- 打开页面时，图标反映当前仓库已保存的信息密度；默认密度为标准，因此默认显示两颗星。
- 用户在密度菜单选择精简、标准或详细后，AI 生成按钮图标立即切换为对应星级。
- 不同仓库继续沿用现有的密度独立保存逻辑；切换仓库时图标随当前仓库的密度恢复。
- AI 正在生成时，星级图标整体隐藏，继续显示现有的旋转加载图标。
- 生成完成、取消或失败后，恢复当前密度对应的星级图标。
- 按钮的中文 `aria-label` 与 `title` 继续包含当前密度，星星本身作为装饰元素，不重复暴露给读屏软件。

## 实现边界

- `aiControlPresentation` 继续作为密度、生成状态与按钮展示状态之间的唯一转换入口。
- `renderCommitWebviewHtml` 输出固定的星群容器和加载图标，不为每个密度复制按钮结构。
- `commit-client` 只更新星群容器的密度状态和生成状态，不替换按钮节点。
- `main.css` 负责三种固定画布构图和加载状态显隐。
- 不调整 AI 密度菜单、提交按钮、提交信息输入区和三分区布局。

## 验收标准

1. 精简、标准、详细分别清晰显示 1、2、3 颗星。
2. 三种密度下按钮均为 `28 × 28px`，图标画布均为 `16 × 16px`。
3. 切换密度时按钮及相邻控件不位移、不伸缩。
4. 默认标准状态显示两颗星。
5. 生成过程中只显示旋转加载图标，结束后恢复正确星级。
6. 切换仓库后图标与该仓库已保存的密度一致。
7. 深色、浅色和禁用状态均继承 VS Code 主题颜色。
8. 现有提交、提交并推送、AI 生成及密度菜单行为不受影响。

## 测试策略

- 单元测试覆盖三种密度的展示状态映射以及生成中的加载状态。
- HTML 渲染测试覆盖固定星群结构、默认标准密度和加载图标。
- 客户端测试覆盖密度切换、生成开始及生成结束时的状态更新。
- 完整运行类型检查、代码检查、单元测试和 VS Code Extension Host 验收。
