# Gitool 未跟踪描述与推送可用性设计

## 范围

本次只修改当前变更文件描述和提交历史标题栏的推送按钮状态。提交历史继续使用现有原生 TreeView，不修改历史拓扑、展开方式、拉取或刷新行为。

## 未跟踪文件描述

未跟踪文件节点继续显示当前文件图标、目录和“未跟踪”文字，但不再追加重复的 `?`。文件资源装饰提供的 Git 状态字符不由本次修改处理。

## 推送按钮可用性

使用扩展上下文键 `gitool.canPushAll` 驱动 `gitool.pushAll` 命令的 `enablement`，使按钮保持在提交历史标题栏原位置，并在不可推送时显示为禁用状态，而不是隐藏。

按钮仅在以下条件全部满足时启用：

- 工作区受信任；
- 当前存在仓库和非游离本地分支；
- 当前仓库至少配置一个远程；
- 当前没有正在执行的仓库写入或同步操作；
- 已设置上游时，本地领先数大于零且落后数为零；
- 未设置上游时，视为当前分支尚未发布，允许选择已配置远程并建立上游。

没有远程、已同步、落后于上游、游离 HEAD、未信任工作区或操作进行中时禁用推送按钮。命令执行层原有的状态校验继续保留，不能只依赖界面禁用保证安全。

## 状态更新

扩展激活时立即计算一次上下文键；仓库切换、刷新、提交、拉取、推送、远程配置和仓库监听事件触发服务状态变化后重新计算。上下文键控制器随扩展运行时一起释放。

## 验证

- 单元测试确认未跟踪文件描述不含 `?`；
- 单元测试覆盖无仓库、无远程、已同步、领先、落后、无上游、游离 HEAD、未信任和操作中状态；
- 贡献点测试确认推送命令使用上下文键控制 `enablement`；
- 全量测试、类型检查、ESLint、构建和 Extension Host 验收通过后重新打包安装。
