# Gitool 未跟踪描述与推送可用性设计

## 范围

本次修改当前变更文件描述、提交成功反馈、两个推送入口的可用状态和提交历史引用显示。提交历史继续使用现有原生 TreeView，不修改历史拓扑、展开方式、拉取或刷新行为。

## 未跟踪文件描述

未跟踪文件节点继续显示当前文件图标、目录和“未跟踪”文字，但不再追加重复的 `?`。文件资源装饰提供的 Git 状态字符不由本次修改处理。

## 推送按钮可用性

使用扩展上下文键 `gitool.canPushAll` 驱动 `gitool.pushAll` 命令的 `enablement`，使按钮保持在提交历史标题栏原位置，并在不可推送时显示为禁用状态，而不是隐藏。

按钮仅在以下条件全部满足时启用：

- 工作区受信任；
- 当前存在仓库和非游离本地分支；
- 当前仓库至少配置一个远程；
- 当前没有正在执行的仓库写入或同步操作；
- 已设置上游时，本地领先数大于零且落后数为零；
- 未设置上游时，视为当前分支尚未发布，允许选择已配置远程并建立上游。

没有远程、已同步、落后于上游、游离 HEAD、未信任工作区或操作进行中时禁用推送按钮。命令执行层原有的状态校验继续保留，不能只依赖界面禁用保证安全。

提交信息区的“提交并推送”同样要求当前仓库至少配置一个远程。没有远程时该按钮保持显示但禁用，“仅提交”仍然可用。

## 操作反馈

普通提交成功或提交并推送全部成功后，提交信息区保留成功文字和提交哈希。提交视图内容必须在自身边界内滚动；成功状态出现时主动把反馈行滚动到可见区域，不能被下方“当前变更”原生视图遮挡。

运行中状态、提交失败、推送失败以及推送失败后的重试入口继续显示。提交已经创建但推送失败属于需要用户处理的部分失败，保留提交哈希和错误信息。

## 历史引用显示

保持公开 TreeView API，不恢复历史 Webview。提交节点左侧继续使用原生主题图标区分 HEAD、本地分支、远程分支和普通提交；右侧引用文字从 `HEAD main · origin/main` 精简为 `main · origin/main`。同一提交的全部引用仍然显示。

公开 TreeView 不提供 SCM Graph 内部使用的多枚彩色行内徽标，因此不仿造彩色胶囊。历史引用显示优化必须作为最后一个独立 Git 提交，不能与其他功能修复混合；如果视觉验收不通过，只回滚该提交。

## 状态更新

扩展激活时立即计算一次上下文键；仓库切换、刷新、提交、拉取、推送、远程配置和仓库监听事件触发服务状态变化后重新计算。上下文键控制器随扩展运行时一起释放。

## 验证

- 单元测试确认未跟踪文件描述不含 `?`；
- 单元测试覆盖无仓库、无远程、已同步、领先、落后、无上游、游离 HEAD、未信任和操作中状态；
- Webview 单元测试确认无远程时禁用“提交并推送”，但不禁用满足提交条件的“仅提交”；
- Webview 单元测试确认完整成功保留文字并触发反馈显现，部分推送失败继续显示错误和重试入口；
- 贡献点测试确认推送命令使用上下文键控制 `enablement`；
- 历史节点测试确认引用文字精简且原生主题图标优先级不变；
- 全量测试、类型检查、ESLint、构建和 Extension Host 验收通过后重新打包安装。

## 提交边界

功能修复先提交并完成验证。历史引用显示优化最后单独提交，使其可以独立回滚而不撤销未跟踪描述、成功反馈和按钮状态修复。
